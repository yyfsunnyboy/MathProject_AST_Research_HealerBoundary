### AST Active Healer 可修復性邊界研究 — Math16 全量閉環

> 日期:2026-07-20|狀態:**實驗完成,基準凍結**(commit `d9aa264c`)
> v2 修正:失敗層統計表由 144 格逐格重新清點,通過三重加總斷言(各模型加總=48、四層互斥加總=FAIL 數、與獨立凍結的 eligible 數 34/26 交叉吻合);修正 Gemini 失敗組成措辭。

## 一、實驗設計(一段話)

16 題國中會考錨定題 × 3 種提示條件(Ab1 裸考 / Ab2g 格式須知 / Ab2d 工具引導)× 3 個模型(Gemini 3.5 Flash 雲端、Qwen 3.5 4B / 9B 本地),共 **144 格**,固定 seed、first-attempt only、prompt 凍結存證。失敗格再經凍結的 deterministic Healer(3 條 L2 + 3 條 L1 規則)做 Ab3 修復輪,全程「預測先鎖 hash、後執行」。

## 三、研究結論(四層)

**結論一:模型能力影響的不只是正確率,也影響錯誤深度。**
本 cohort 中,4B 常卡在語法、結構與執行(結構+執行層 32/42);9B 較多轉為答案錯(語意層 8→15);Gemini 大多直接成功,剩下少量答案或格式錯誤。模型越強,Healer 可處理的錯誤窗口未必變大,而是往不同位置移動。

**結論二:Deterministic Healer 的有效區域非常窄。**
可安全修復的錯誤必須同時具備:局部、唯一、可靜態驗證、不需重算答案、不需猜測語意、修補後保留原核心計算。此類錯誤在早期 cohort(113/114 會考題批次)曾出現並救回 2 格,但在正式 Math16 run_002 中極為稀少(僅 2/60 eligible 格通過此門檻,且修復後均暴露更深層失敗)。

**結論三:多重錯誤併發是小模型的重要邊界。**
許多表面上只有單一 SyntaxError 的程式,實際同時存在第二處 delimiter 錯誤、prose 殘留、invalid token、schema 錯誤、未定義函數或演算法錯誤(10 格候選經窮舉驗證均因多重錯誤被安全攔截)。單點修復常只能打開下一層錯誤,而非直接救回。

**結論四:安全 abstain 本身就是成果。**
全程未曾:改答案、重寫演算法、依 evaluator 回饋試 patch、為單一 cell 寫補丁、把正確程式修壞。PASS controls 零 regression、144/144 預測命中。Healer 的安全性強於其救回率——它幾乎不亂動;而 coverage 低是本 cohort 失敗性質(多重錯誤與語意錯誤佔絕對多數)所決定的,並非規則設計不力:針對最高頻的 prose 殘留模式,本研究已設計規則並經 qualification 證明該類「不具安全可切割性」(9 格全數正確 abstain),此陰性結果即為邊界證據。

## 四、最終結論(定稿,可直接引用)

> **我們最後找到的不是「Healer 可以修很多錯」,而是 Healer 的安全邊界:它適合修單一、局部、唯一、可驗證的結構錯誤;遇到多重錯誤或語意錯誤時應 abstain。這個邊界在不同模型上會移動。**

## 五、方法論可信度

| 機制 | 實績 |
|---|---|
| 預測先鎖(SHA-256 + commit 後才執行) | 144/144 命中 |
| 負向對照(好的不動) | 累計零誤觸、PASS controls 零 regression |
| H0 不可變(byte-level 凍結,rev2 協議) | 144 格 hash 驗證通過 |
| 誠實揭露 | 1 處證據缺口以 EVIDENCE_GAP_NOTE 如實入版控;L1 pass 規則曾主動撤回 |
| 評分方式 | 確定性程式執行 + 獨立驗算比對,非 LLM-as-judge |

## 六、與早期 cohort 的關係(避免數字混淆)

7/18 前的 113/114 會考題 pilot(另一批資料)曾達成 2 格救回、3 條 L2 規則轉正;Math16 run_002 為規模更大、紀律更嚴的正式 cohort,淨救回 0。兩批不可加總,但互相印證:救回僅發生於「核心計算正確、只是包裝/接線錯」的狹窄條件,且該條件在小模型輸出中稀有。
